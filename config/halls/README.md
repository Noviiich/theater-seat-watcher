# Профили залов

Здесь размещаются проверенные YAML-профили топологии и оценки мест. Имя файла
равно `<profile_id>.yaml`; профиль выбирается одноимённым значением подписки.
Перед live-приёмкой fingerprint и физический порядок мест сверяются с актуальной
схемой зала. Профиль не содержит данные покупателя, cookies или ссылки оплаты.

Помимо полей топологии из `docs/seat-selection.md`, runtime требует секцию:

```yaml
selection:
  row_quality: {"1": "0.50", "6": "1.00"}
  weights: {row: "0.40", center: "0.35", price: "0.15", aisle: "0.10"}
  min_quality: "0.60"
  view_axis_x: "500"
  normalization_width: "500"
  aisle_quality: {stalls-r6-left: "0.80"}
```

Десятичные коэффициенты задаются строками, чтобы не вносить float в решения.

Для подготовки черновиков всех публичных схем используйте:

```bash
uv run python scripts/generate_hall_profiles.py
```

Команда выполняет только публичные GET-запросы, создаёт один файл на уникальный
fingerprint и не перезаписывает существующие профили. Она консервативно разрывает
ряд на большом промежутке; до live-приёмки вручную проверьте проходы, сцену,
сегменты и оценки мест.

Чтобы увидеть действие коэффициентов на текущей доступности, сформируйте полный
список соседних пар в уже заданном порядке:

```bash
uv run python scripts/rank_hall_pairs.py config/halls/hall-16-66d533219367.yaml
```

Рядом с профилем появится файл `*.pairs.yaml`. Он содержит provider ID, видимые
номера мест, ряд, стоимость, итоговую оценку каждой физически допустимой пары и
поле `currently_free`. По умолчанию это полный список для настройки коэффициентов;
для просмотра только свободных пар добавьте `--available-only`. Меняйте коэффициенты
в основном YAML и запускайте команду снова; отчёт перезаписывается.
