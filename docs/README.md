# Документация theater_tickets

26.09.2026 добавлен [режим 70 отдельных билетов для организации](organization-booking.md):
один билет — один заказ — одна ссылка. Он использует отдельные слоты мест,
сохраняет ограничения продавца и не меняет существующие подписки автоматически.
Описанный ниже прежний сценарий соседних мест остаётся совместимым режимом.

Документация обновлена 21 сентября 2026 года. Исследование публичных страниц
и запросов чтения QuickTickets выполнено 16 сентября. Базовый пакет, чистый
домен, durable discovery, локальное планирование лимитов, валидирующий checkout
adapter, сохраняемый планировщик двадцатиминутных циклов и persistent outbox уже
соединены полным сценарием. Реализован устойчивый lifecycle независимых фоновых
задач, single-instance lease, graceful shutdown и runtime-диагностика.
Dry-run развёртывание и production entrypoint завершены на шаге 19; шаг 20,
ограниченная приёмка live-бронирования, остаётся открытым.

Уточнение пользователя: оплата удержанного заказа доступна **20 минут**. Для каждого нового
подходящего сеанса бот оформляет первый заказ сразу, а затем повторяет подбор
и оформление через 1200 секунд, присылая новую ссылку при доступных удобных
соседних местах. Оплата не завершает цикл автоматически; это делает `/stop`,
пауза или окончание отслеживания. Статус предыдущей оплаты не запрашивается.

Переносимость ссылки оплаты подтверждена пользовательским HAR и открытием в
другом браузере. Исследовательский `initAnytickets` подтверждён как изменяющий
запрос: он создаёт временное удержание. Адаптер признаёт успех только после
полной проверки заказа и payment handoff; неоднозначный ответ блокирует повтор.
Оплата не выполнялась и не автоматизируется. Product TTL и интервал нового цикла
равны 1200 секундам. Startup recovery неоднозначных операций реализован в шаге
14; без подтверждённого provider lookup он безопасно требует внимания человека.
