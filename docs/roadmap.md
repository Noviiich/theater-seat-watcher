# Roadmap по отдельным коммитам

Каждый пункт — один самостоятельный логический commit с результатом и проверкой.
Названия коммитов предложены заранее; выполненные изменения ещё не закоммичены.
Отметка `[x]` означает наличие результата в файлах, а не наличие Git-коммита.
В исходной рабочей папке при исследовании Git-репозитория не было; инициализация
репозитория и первый commit относятся к отдельному началу разработки.

Стратегия: проверить оформление рано → создать read-only основу → подобрать места
→ добавить безопасное оформление и восстановление → подключить автоматический
сценарий → развернуть. Никакой этап не делает изменяющие запросы по умолчанию.

  двадцатиминутная политика Renewals и обязательный профиль ФИО/телефон.

  отсутствие секретов в diff.

  сразу после успешного POST место имеет `short_lock`. В одном предыдущем
  сценарии `anytickets` открыл форму `/ordering/confirm` с обязательными
  `email` и `lastname`; повторный `confirm` с контролируемым тестовым контактом
  ответил HTTP 200 без redirect, а место осталось `short_lock` как минимум две
  минуты. В свежем воспроизведении `anytickets` вернул HTTP 302, который не был
  открыт и чей `Location` не сохранён. Финальное подтверждение, TTL, ссылка
  оплаты и reconciliation не завершены. Новый POST не запускать до
  подтверждённого терминального исхода текущего lock; следующий сценарий должен
  сохранять cookie-контекст и очищенно разбирать HTTP 302/ответ confirm.
  Установлено также обязательное поле `selectAnyplacesCount` для
  `/ordering/anytickets`: без него сервер возвращает на страницу сеанса при
  сохранённом hold. С ним форма confirm доступна, но `confirm` возвращает
  пустой HTTP 200 без ссылки. Предоставленный HAR подтвердил страницу
  `/payment/order/<opaque-order-token>`, polling `/payment/check_payment` и
  срок оплаты 1200 секунд. После последнего confirm QuickTickets начал обрывать
  TLS даже для read-only запросов; headless Chrome получил тот же TLS
  `net_error -100`. Пользователь подтвердил открытие payment URL в другом
  браузере. Проверка terminal status намеренно исключена: renewals создают
  новый цикл через 1200 секунд до `/stop` или `watch_until`. Шаг 02 завершён;
  live checkout реализуется только в шаге 13.
  Подробности — в quicktickets-api.md.
