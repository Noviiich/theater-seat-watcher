# Выбор соседних и удобных мест

Новый режим [70 отдельных билетов](organization-booking.md) выбирает первое
свободное место из свежего inventory без оценки геометрии и сортировки. Уже
назначенные другим слотам места исключаются; при повторе успешного заказа
проверяется только ранее закреплённое место. Описанный ниже алгоритм соседства
применяется к прежним подпискам с одним заказом на группу.

## Модель

`Seat`: provider ID, hall ID, block, метка ряда, метка места, координаты,
доступность, цена в копейках и ограничения. `SeatGroup`: упорядоченные ID,
сумма, компоненты оценки, объяснение. Алгоритм — чистая функция:

```text
rank_groups(inventory, hall_profile, preferences, ticket_count) -> ranked groups
```

Входной inventory строится из схемы **и** свежей карты занятости. Геометрия
кешируется по версии профиля; цена и доступность заново проверяются перед заказом.
Лучшей считается группа по явно заданным предпочтениям, а не объективная
«лучшая видимость», которую нельзя доказать по координатам.

## Соседство — обязательное ограничение

Все N мест принадлежат одному залу, сектору, ряду и непрерывному сегменту без
проходов. ID места и его отображаемый номер не определяют соседство. Чётные,
нечётные, обратные номера и буквенные ряды допустимы.

Профиль содержит `row_segments`: упорядоченные по физическому расположению
цепочки ID и границы проходов. Можно использовать подтверждённые связи
соседства провайдера; в исследованном JSON явные связи пока не обнаружены.
Координаты помогают подготовить профиль и обнаружить подозрительные разрывы,
но автоматически считать любые близкие прямоугольники соседними нельзя.
Профиль проверяется по визуальной схеме, включая сцену, проходы и отдельные блоки.

Fingerprint топологии учитывает hall ID, ID/ряды/координаты/формы мест; текущую
занятость и цены в него не включать. При несовпадении профиля со схемой подбор
для live возвращает `profile_mismatch`. Уведомление и просмотр остаются доступны.

## Два источника групп

1. **Список предпочтительных групп:** пользователь перечисляет конкретные
   сочетания мест и их приоритет. Проверяем их по топологии и текущим ограничениям,
   затем ранжируем подходящие.
2. **Автоматическая генерация:** в каждом сегменте выделяем непрерывные свободные
   серии и сдвигаем окно длиной N на одно место. Все окна становятся кандидатами.

Режимы профиля: `manual_only`, `automatic`, `manual_then_auto`. По умолчанию
`manual_then_auto`: сначала допустимые ручные группы, при их отсутствии —
автоматические. Само переключение не ослабляет соседство, бюджет или качество.
Ручная группа содержит ровно N мест; более длинную цепочку задавать сегментом,
а не неявно обрезать группу. Разные N могут иметь разные ручные списки.

Иллюстративный профиль; **ID ниже вымышленные**, не использовать для заказов:

```yaml
profile_id: example-hall-v1
hall_id: example-hall
topology_fingerprint: REPLACE_AFTER_VERIFICATION
mode: manual_then_auto
row_segments:
  - id: stalls-r6-left
    block: stalls
    row: "6"
    seat_ids: [demo-101, demo-102, demo-103, demo-104]
  - id: stalls-r6-right
    block: stalls
    row: "6"
    seat_ids: [demo-105, demo-106, demo-107, demo-108]
preferred_groups:
  - id: preferred-pair
    priority: 1
    seat_ids: [demo-102, demo-103]
row_quality: {"6": 1.0, "7": 0.95, "1": 0.45}
weights:
  row: 0.40
  center: 0.35
  price: 0.15
  aisle: 0.10
min_quality: 0.60
```

Реальный профиль дополнительно задаёт геометрию центральной оси/сцены,
допустимые ряды/секторы, места с ограниченной видимостью и отношение к проходу.
Первый ряд не считается лучшим по умолчанию. Неизвестную оценку ряда не заменять
максимальной: для live профиль должен покрывать допущенные к выбору ряды.

## Фильтрация и оценка

Сначала отбрасываем группы с занятыми/неизвестными/отключёнными местами,
неверным соседством, ограничениями тарифа, неподходящим сектором/рядом,
ценой выше лимита или количеством выше sale capability. Места без нумерации
не могут удовлетворить требование соседних кресел при N > 1. При N = 1
свободный элемент `hall/hall.response.places` с пустыми и рядом, и номером
допускается как отдельное входное место, если весь зал содержит только такие
места и указан `seat_profile_id=auto`: проверяются цена, лимиты, статус и
результат checkout; геометрическое качество ему не приписывается. Выбирается
самое дешёвое свободное место, затем по ID. Для смешанного зала и явного
профиля обычная проверка топологии не обходится. Частично заполненные ряд или
номер отклоняются.

После жёстких ограничений оцениваем группу целиком:

```text
quality(G) = w_row * row_quality(G)
           + w_center * center_quality(G)
           + w_price * price_quality(G)
           + w_aisle * aisle_quality(G)
```

Все компоненты в [0, 1], неотрицательные веса в сумме дают 1. `row_quality`
задаётся профилем. `center_quality = clamp(1 - distance(group_center, view_axis)
/ normalization_width, 0, 1)` использует центральную ось сцены и ширину из
профиля; `normalization_width > 0`. `group_center` — центр крайних мест группы.
Ось и метрика расстояния задаются для сектора: не всегда достаточно среднего X.

`price_quality = clamp(1 - seats_total / max_order_total, 0, 1)` при положительном
бюджете; это предпочтение цены кресел, а окончательная комиссия проверяется
checkout. `aisle_quality` задаёт профиль: например, предпочтение/избегание
края сегмента. Неизвестные обязательные компоненты делают профиль непригодным.
Группы ниже `min_quality` отбрасываются, включая ручные.

Сортировка:

1. Источник согласно mode: ручные перед автоматическими при `manual_then_auto`.
2. Для ручных — меньший `priority` лучше; для автоматических приоритет одинаковый.
3. Больший `quality`.
4. Меньшая сумма мест.
5. Стабильный ключ `(segment_id, physical_start_index, tuple(seat_ids))`.

Качество считать воспроизводимо, например Decimal с фиксированной точностью.
Возвращать несколько лучших групп и объяснение: «Ряд 6, центр, два места подряд,
сумма 2400 ₽; группа следующего ряда ниже по предпочтению ряда».

## Пример соседства

```text
Сегмент A: a1 — a2 — a3 — a4     ПРОХОД     Сегмент B: b1 — b2 — b3
Состояние:  +    +    X    +                   +    +    +
N = 2
Группы: [a1,a2], [b1,b2], [b2,b3]
Запрещено: [a2,a4] (занятое место между ними), [a4,b1] (проход).
```

Для `N=1` тот же алгоритм оценивает одиночные места. Для свободной серии длиной
K существует `max(0, K-N+1)` окон. С префиксными суммами/оценками генерация и
подсчёт — O(M), сортировка C групп — O(C log C). Не перебирать все сочетания мест.

## Повторный подбор каждые двадцать минут

Через 1200 секунд от начала удержания начинается новый цикл оформления для того
же Candidate. Статус оплаты предыдущего заказа не запрашивается. В каждом
цикле заново загружаются занятость и цены и вычисляется рейтинг всех допустимых
групп. Старые seat_ids не переиспользуются без проверки. Можно выбрать прежнюю
группу, если она снова свободна и лучшая; иначе выбирается другая удобная группа.
Количество, соседство, бюджет и min_quality сохраняются во всех циклах.

Новая группа может отличаться от предыдущей — сообщение оплаты показывает
актуальные ряд, места и сумму. До наступления локального срока 1200 секунд
следующий подбор не приводит к checkout. Активную бронь не отменяем для смены
группы. Нет подходящих мест — следующая
проверка через 180 секунд до watch_until, без ссылки на несуществующий заказ.

## Гонка и проверка

Выбрать лучшую группу → обновить inventory → повторно проверить → оформить.
Если получен однозначный отказ из-за занятости и нет удержания, обновить snapshot
и попробовать следующую группу, максимум три попытки в одном проходе worker.
Новая проверка должна исключать уже отвергнутую группу для того же snapshot.
После лимита попыток — ожидание до watch_until, без бесконечного быстрого цикла.
Следующий проход выполняется через 180 секунд. Технические попытки внутри
прохода относятся к одному RenewalCycle; новый цикл после локального срока
имеет новый cycle_no. Успешную бронь не продлеваем повторным POST той же попытки.
Если результат оформления неизвестен, переход к другой группе запрещён до
reconcile. Лимиты бюджета учитываются до каждой изменяющей операции.

Тестовые случаи: N=1; чётная/обратная нумерация; проход; занятое место внутри;
одинаковые номера в разных секторах; смешанные цены; нехватка N подряд при
достаточном общем числе; ручная группа вне топологии; истёкший inventory;
unknown/disabled status; смена схемы; одинаковые оценки; max sale quantity;
конфликт лучшей группы; отсутствие подходящих групп. Property-тесты проверяют,
что любая возвращённая группа имеет N уникальных доступных соседних мест.
Дополнительные сценарии циклов: прежняя группа освободилась; прежние места
выкуплены другим человеком; новая лучшая группа; повышение цены; свободных
соседних мест временно нет; оплата старого заказа прекращает подбор для оформления.
